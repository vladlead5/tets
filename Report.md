## 1. Введение

Языковое моделирование (Language Modeling) — задача предсказания следующего токена в последовательности. Это фундаментальная задача NLP, лежащая в основе систем генерации текста, машинного перевода, суммаризации.

В данной работе мы сравниваем несколько классов нейросетевых архитектур:
- **RNN** — базовая рекуррентная сеть
- **LSTM** — улучшенная RNN с воротами памяти
- **BiLSTM** — двунаправленный LSTM
- **Transformer (GPT)** — современная attention-based архитектура

Дополнительно исследуется fine-tuning предобученной GPT-2 модели.

---

## 2. Постановка задачи

**Задача**: языковое моделирование (Language Modeling)

Дана последовательность токенов $x_1, x_2, \ldots, x_T$. Модель должна предсказать вероятность следующего токена:

$$P(x_{t+1} \mid x_1, x_2, \ldots, x_t)$$

**Метрика**: Perplexity (PPL):
$$\text{PPL} = \exp\left(\frac{1}{T} \sum_{t=1}^{T} -\log P(x_t \mid x_{<t})\right)$$

Чем меньше PPL — тем лучше модель.

Для char-level моделей дополнительно используется **BPC** (Bits Per Character):
$$\text{BPC} = \frac{\text{Loss}}{\ln(2)}$$

### Шаги очистки:

1. **Удаление непечатаемых символов** — убираем всё кроме ASCII 0x20–0x7E и `\n`

## 5. Токенизация

### 5.1 Char-level (посимвольная)

Каждый символ — отдельный токен.

- **Словарь**: 65 токенов (все уникальные символы в тексте)
- **Длина последовательности**: 100 символов
- **Encode**: `'Hello' → [33, 40, 47, 47, 50]`

**Плюсы**: маленький словарь, нет OOV, работает на любом языке  
**Минусы**: длинные последовательности, слабый семантический уровень

### 5.2 Word-level (пословная)

Каждое слово/знак препинания — отдельный токен.

- **Словарь**: 8,000 токенов (min_freq=2)
- **Специальные токены**: `<PAD>`, `<UNK>`, `<SOS>`, `<EOS>`
- **OOV rate**: ~1–3% (редкие слова → `<UNK>`)
- **Длина последовательности**: 50 слов

Распределение частот слов подчиняется **закону Zipf** — небольшое число слов встречается очень часто, большинство слов редкие.

**Плюсы**: короткие последовательности, высокая семантика  
**Минусы**: большой словарь, проблема OOV

### 5.3 BPE (Byte Pair Encoding)

Субсловная токенизация — баланс между char и word.

- **Словарь**: 3,000 токенов
- **Алгоритм**: обучен на датасете с нуля через HuggingFace `tokenizers`
- **Сжатие**: BPE в ~2.5x короче char-level

**Пример**:
```
"Shakespeare" → ["Sh", "akes", "pe", "are"]
```

**Плюсы**: нет OOV, умеренная длина, разумный размер словаря  
**Минусы**: требует обучения tokenizer, менее интерпретируем

### Сравнение токенизаций

| Токенизация | Vocab size | Длина seq | Сжатие |
|-------------|-----------|-----------|--------|
| Char | 65 | 100 | 1x |
| BPE | 3,000 | ~40 | ~2.5x |
| Word | 8,000 | 50 | ~4x |

## 6. Архитектуры моделей

### 6.1 Simple RNN

```
Embedding(vocab, 128) → RNN(128→256) → Dropout(0.3) → Linear(256→vocab)
```

Ванильная RNN: скрытое состояние обновляется как:
$$h_t = \tanh(W_{hh} h_{t-1} + W_{xh} x_t + b)$$

**Проблема**: vanishing gradient — сложно учить зависимости на 10+ шагов.

**Параметры**: embed_dim=128, hidden=256, layers=1, dropout=0.3

### 6.2 LSTM (однослойная и многослойная)

```
Embedding(vocab, 128) → LSTM(128→256, layers=1/2) → Dropout(0.3) → Linear(256→vocab)
```

LSTM добавляет ворота:
- **Forget gate**: что забыть из памяти
- **Input gate**: что добавить в память
- **Output gate**: что выдать наружу

Позволяет учить зависимости на 100+ шагов.

**Конфигурации**:
- `LSTM-1layer`: 1 слой, hidden=256
- `LSTM-2layer`: 2 слоя, hidden=256, dropout между слоями

### 6.3 Bidirectional LSTM

```
Embedding(vocab, 128) → BiLSTM(128→256×2) → Dropout(0.3) → Linear(512→vocab)
```

Обрабатывает последовательность в обоих направлениях:
- Forward: слева направо
- Backward: справа налево

Выход: конкатенация forward и backward hidden states (512-мерный вектор).

**Особенность для генерации**: на инференсе BiLSTM не может использовать будущий контекст, поэтому при генерации используется только forward-направление.

### 6.4 GPT-like Transformer

Реализован с нуля на PyTorch. Архитектура:

```
TokenEmbedding(vocab, 128)
+
PositionalEmbedding(max_seq, 128)
    ↓
TransformerBlock × 4:
  LayerNorm → MaskedMultiHeadAttention(8 heads) → Residual
  LayerNorm → FeedForward(128→512→128) → Residual
    ↓
LayerNorm
    ↓
Linear(128→vocab)  [tied weights с TokenEmbedding]
```

**Causal mask** гарантирует, что позиция `i` видит только токены `j ≤ i`.

**Tied weights**: матрица эмбеддингов разделяется с матрицей lm-головы — стандартная техника уменьшения параметров.

**Инициализация**: нормальное распределение N(0, 0.02) как в GPT-2.

**Параметры**: embed_dim=128, num_heads=4, num_layers=4, max_seq_len=100

### 6.5 Fine-tuning distilgpt2

**distilgpt2** — дистиллированная версия GPT-2:
- 82M параметров
- Обучен на WebText (40GB текста)
- В 2x быстрее GPT-2 при сохранении ~97% качества

Процесс fine-tuning:
1. Загружаем предобученную модель и токенизатор
2. Токенизируем наш датасет GPT-2 tokenizer'ом
3. Дообучаем все параметры (full fine-tuning) на 3 эпохи
4. Optimizer: AdamW, lr=5e-5, weight_decay=0.01
5. Scheduler: CosineAnnealingLR

## 7. Процесс обучения

### Training Pipeline

Реализован в `src/training/trainer.py`. Поддерживает все типы моделей через параметр `model_type`.

```python
history = train_model(
    model=model,
    train_loader=train_loader,
    val_loader=val_loader,
    model_name='gpt_char',
    model_type='transformer',  # или 'rnn'
    num_epochs=10,
    lr=3e-4,
    clip_grad=1.0,             # gradient clipping
    patience=5,                # early stopping
    checkpoint_dir='outputs/checkpoints',
    device=device,
    use_amp=True,              # mixed precision (только CUDA)
)
```

### Гиперпараметры

| Параметр | RNN/LSTM/BiLSTM | GPT |
|----------|-----------------|-----|
| Optimizer | Adam | Adam |
| Learning rate | 1e-3 | 3e-4 |

| Grad clipping | 1.0 | 1.0 |
| Dropout | 0.3 | 0.1 |
| Scheduler | ReduceLROnPlateau | ReduceLROnPlateau |

### Early Stopping

Если val_loss не улучшается 5 эпох подряд — обучение прерывается. Лучший чекпоинт сохраняется автоматически.

### Итоговая сравнительная таблица (char-level)

| LSTM-1layer | 433K | 4.70 | 2.23 | ~52s | Высокая | Хорошее |

### Выводы по сравнению:

**SimpleRNN** — самая слабая модель. Страдает от vanishing gradient. Генерирует повторяющиеся паттерны.

**LSTM-1layer vs LSTM-2layer** — добавление второго слоя даёт +0.23 PPL при умеренном увеличении времени обучения. Двухслойная LSTM — хороший баланс качества и скорости.

**BiLSTM** — на обучении выигрывает у однонаправленных LSTM (видит будущий контекст), но при генерации уступает, т.к. вынужден использовать только forward-направление.

**GPT (Transformer)** — лучший результат среди моделей "с нуля". Self-attention позволяет явно обращаться к любой позиции в контексте. Особенно хорошо справляется с длинными зависимостями (рифмы, диалоги).

**Transformer vs RNN/LSTM**:
- **Transformer выигрывает**: качество на длинных зависимостях, параллелизм на GPU
- **RNN/LSTM лучше**: меньше памяти, инференс на CPU, проще для коротких последовательностей

## 11. Анализ ошибок

### SimpleRNN

**Типичные ошибки**:
- Застревание в петлях: "the the the the..."
- Исчезновение контекста через 10–15 символов
- Случайные символы/слова без связи с контекстом

**Причина**: vanishing gradient — модель не обучается учитывать далёкий контекст.

### LSTM

**Типичные ошибки**:
- Семантическое повторение на уровне фраз
- Потеря темы через 50–70 слов
- Иногда бессмысленные комбинации слов

**LSTM лучше RNN** — избегает vanishing gradient, но всё ещё страдает от ограниченного контекста.

### BiLSTM

**Специфическая проблема**: при генерации backward-направление не используется, поэтому модель генерирует хуже, чем при валидации. Это фундаментальное ограничение BiLSTM для задачи генерации.

### GPT Transformer

**Типичные ошибки**:
- Hallucinations: иногда генерирует несуществующих персонажей
- При temperature=1.0+ текст становится бессвязным
- При greedy — часто застревает в повторениях

**Лучшая стратегия**: top-k sampling (k=40) при temperature=0.8.

## 12. Fine-tuning GPT-2

### Мотивация

Обучение с нуля требует много данных и вычислительных ресурсов. Fine-tuning позволяет адаптировать уже обученную модель к конкретному домену за минуты.

### Процесс

1. **Загрузка модели**: distilgpt2 (82M параметров, GPT-2 BPE tokenizer)
2. **Токенизация**: GPT-2 BPE tokenizer → ~220K токенов
3. **Обучение**: 3 эпохи, lr=5e-5, AdamW, CosineAnnealingLR
4. **Batch size**: 4 (для совместимости с CPU), seq_len=128

### Результаты fine-tuning

Уже после первой эпохи модель начинает генерировать текст в стиле Шекспира. За 3 эпохи:
- Val Loss: 3.2 → 2.78
- Val PPL: 24.5 → 16.1
- Стиль генерации заметно приближается к датасету

### Сравнение с GPT с нуля

| Аспект | GPT с нуля | Fine-tuned distilgpt2 |
|--------|-----------|----------------------|
| Параметры | 1.2M | 82M |
| Обучение | 10 эпох | 3 эпохи |
| Время | ~12 мин | ~5 мин |
| Качество генерации | Хорошее | Отличное |
| Разнообразие | Умеренное | Высокое |

Fine-tuning предобученной модели значительно превосходит обучение с нуля даже при меньших затратах времени.

## 13. Итоговые выводы

### Главные выводы:

1. **Transformer (GPT) — лучшая архитектура** для языкового моделирования среди реализованных с нуля. Self-attention лучше справляется с долгосрочными зависимостями.

2. **LSTM превосходит RNN** благодаря механизму ворот. Двухслойная LSTM — лучший баланс между качеством и скоростью для RNN-семейства.

3. **BiLSTM не подходит для генерации** — двунаправленный контекст помогает при обучении, но при генерации используется только половина модели.

4. **BPE — лучший выбор токенизации** для реальных задач. Сочетает преимущества char-level (нет OOV) и word-level (короткие последовательности).

5. **Fine-tuning >> обучение с нуля** при ограниченных ресурсах. distilgpt2 за 3 эпохи превосходит наш GPT за 10 эпох.

### Рекомендации по выбору модели:

| Сценарий | Рекомендация |
|----------|-------------|
| CPU, мало данных | LSTM-2layer + char/BPE |
| GPU, средний датасет | GPT Transformer + BPE |
| Любой датасет, максимум качества | Fine-tuning GPT-2/GPT-3 |
| Интерпретируемость важна | LSTM |
| Минимум параметров | LSTM-1layer + char |
